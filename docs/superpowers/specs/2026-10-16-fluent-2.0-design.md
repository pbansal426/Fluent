## 1. Executive Summary & Vision

Every bureaucratic interaction—whether registering at a medical clinic, renewing a driver's license, applying for benefits, submitting immigration papers, or calling an office over the phone—is fundamentally an exercise in **filling out a form**.

For non-native speakers, elderly adults, and everyday people, this process is fraught with anxiety, jargon, and communication breakdowns. Traditional phone bots and IVRs are notoriously rigid and frustrating, while paper and web forms fail accessibility standards.

**Fluent 2.0** is an **Autonomous, Multilingual Form-Filling and Metacognitive Voice Engine**. It serves as an intelligent intake layer that runs anywhere:
1. **Consumer Chrome Extension (MV3):** Works on any website, patient portal, government service, or PDF.
2. **Kiosk & Embedded Web Widget:** Drops onto physical clinic check-in tablets or hospital websites with zero backend changes.
3. **Telephony & Headless Intake Engine:** Powers conversational phone intake (e.g., medical scheduling, intake desks) where an AI agent gathers demographic and personal data accurately and empathetically over voice.

## 3. Metacognitive Voice & Spelling Intelligence

A major pain point in both web voice assistants and telephone agents is the mishandling of names, street addresses, and emails. Speech recognition frequently produces homophones or slightly garbled phonetic strings.

Fluent 2.0 introduces **Metacognitive Speech Resolution**:

### A. Metacognitive Confidence Assessment
Before writing to a field, the engine assesses:
* **Field Type Sensitivity:** High scrutiny for Legal Names, Street Addresses, Emails, and Policy IDs; lower scrutiny for freeform descriptions.
* **Acoustic & Semantic Confidence:** Detects when speech recognition alternatives (e.g., `event.results[i][j].transcript`) have multiple plausible interpretations.
* **Known Variant Catalog:** Recognizes common spelling splits:
  * *Sara* vs *Sarah*, *Jon* vs *John*, *Marc* vs *Mark*, *Bryan* vs *Brian*, *Shawn* vs *Sean*.
  * Street name suffixes and phonetically tricky names (*Coughlin*, *Worcester*, *Peachtree*).

### B. Natural, Low-Friction Confirmation Strategies
Instead of robotically asking the user to spell every single word (which destroys conversation flow):
1. **High Confidence:** Directly fills the value with zero interruption.
2. **Targeted Variant Check:** When a known variant is spotted, asks a rapid, natural question:
   > *"Got it, Bryan — is that with a Y or an I?"*  
   > *"And is that Sarah with an 'h' at the end?"*
3. **Phonetic Spelling Mode (for unusual surnames or tricky streets):**
   > *"Could you spell that last name for me?"*  
   * The recognizer accepts single letters, spaced letters, or NATO phonetics (*"S as in Sam, M-I-T-H"*), automatically assembling the normalized string.
4. **Email Normalization & Echo:**
   * Automatically normalizes *"john dot doe at gmail dot com"* into `john.doe@gmail.com`.
   * Fast verification check: *"john.doe at gmail.com, correct?"*

## 4. Universal Form Engine: Web, PDF, and Telephony

Fluent's engine is decoupled from the DOM via the **`FormSession`** abstraction:

```javascript
class FormSession {
  // Scans input controls from active webpage
  static fromDOM(document) { ... }
  
  // Extracts AcroForm fields & tooltips from PDF
  static fromPDF(pdfDoc) { ... }
  
  // Ingests schema for headless / phone intake
  static fromSchema(intakeSchema) { ... }
}
```

### Telephony & Phone Intake Mode
* When deployed as a phone agent (via WebSockets / SIP integration with providers like Twilio or LiveKit):
  * Fluent treats the phone call as an invisible form intake session.
  * Uses the exact same cognitive planner, 6th-grade explanations, and metacognitive spelling resolution.
  * When private fields (e.g., SSN or payment card) are reached, it uses **DTMF (touch-tone keypad)** rather than spoken voice, ensuring strict PCI/HIPAA compliance.

## 5. User Experience & Conversational Flow

### A. Non-Intrusive Web Discovery
* When visiting any webpage with forms or opening a PDF in Chrome:
  * An unobtrusive pill appears: *"Need help in your language? (Tap to talk)"*.
  * Clicking opens the **Fluent Side Panel**.

### B. Dynamic Milestones & Visual Hint Cards
* The panel top bar displays: `Section 2 of 4: Contact Information • 3 fields left` alongside a 1-tap Language Switcher pill.
* If a tricky field is reached (e.g. *Insurance Group Number* or *USCIS A-Number*), the assistant speaks a plain-language clue and slides in an annotated illustration of a standard card highlighting exactly where that number is printed.

### C. Fluid Jumps & Corrections
* Users can speak naturally at any point:
  * *"Wait, change my street address to 404 Elm Street"* $\rightarrow$ Updates field immediately, confirms verbally (*"Updated address"*), and resumes where it left off (*"Now, back to your phone number"*).
  * *"Why do you need my income?"* $\rightarrow$ Explains in one sentence, then repeats the question.

### D. Bilingual Staff Verification Card
* At the end of the form, an interactive card displays:
  * All answers side-by-side in the user's native language and the form's official language.
  * 1-click edit buttons for any adjustments.
  * Clear confirmation that the user maintains 100% control to review and submit the form.

## 6. Implementation Architecture & File Layout

* **`extension/lib/agent.js`**: Core conversation orchestrator with dynamic milestone planning and multi-tool execution.
* **`extension/lib/metacognitive.js`**: Phonetic confidence scoring, spelling variant resolution, and name/address verification logic.
* **`extension/lib/live.js` & `speech.js`**: Low-latency VAD, sentence-streaming TTS, and acoustic barge-in.
* **`extension/lib/form-session.js`**: Unified abstraction over DOM, PDF, and headless schemas.
* **`extension/content/scan.js` & `overlay.js`**: Page scanning and translation overlays.
* **`extension/panel/panel.js` & `panel.html`**: Section progress bar, live voice visualizer, document hint cards, and bilingual review card.

## 7. Verification & Safety Guards

1. **Air-Gap Privacy Guard:** All private fields are masked, typed directly, and never sent to the LLM or telephone audio stream.
2. **Corpus Expansion:** Add 25+ test cases covering name spelling variants (*Bryan/Brian*, *Sara/Sarah*), spelled emails, and conversational interruptions to `tests/corpus.json`.
3. **Unit Tests:** Verify `FormSession` across DOM, PDF, and Schema formats, and ensure `Metacognitive` resolver achieves >95% accuracy on phonetic name variants.
