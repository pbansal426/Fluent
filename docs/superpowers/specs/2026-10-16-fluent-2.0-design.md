## 1. Executive Summary & Vision

Every bureaucratic interaction—whether registering at a medical clinic, renewing a driver's license, applying for benefits, submitting immigration papers, or calling an office over the phone—is fundamentally an exercise in **filling out a form**.

For non-native speakers, elderly adults, and everyday people, this process is fraught with anxiety, jargon, and communication breakdowns. Traditional phone bots and IVRs are notoriously rigid and frustrating, while paper and web forms fail accessibility standards.

**Fluent 2.0** is an **Autonomous, Multilingual Form-Filling and Metacognitive Voice Engine**. It serves as an intelligent intake layer that runs anywhere:
1. **Consumer Chrome Extension (MV3):** Works on any website, patient portal, government service, or PDF.
2. **Kiosk & Embedded Web Widget:** Drops onto physical clinic check-in tablets or hospital websites with zero backend changes.
3. **Telephony & Headless Intake Engine:** Powers conversational phone intake (e.g., medical scheduling, intake desks) where an AI agent gathers demographic and personal data accurately and empathetically over voice.

## 3. Metacognitive Voice & Spelling Intelligence

A major pain point in both web voice assistants and telephone agents is the mishandling of names, street addresses, and emails. Speech recognition frequently produces homophones or slightly garbled phonetic strings.

Fluent 2.0 introduces **Metacognitive Speech Resolution**:

### A. Metacognitive Confidence Assessment
Before writing to a field, the engine assesses:
* **Field Type Sensitivity:** High scrutiny for Legal Names, Street Addresses, Emails, and Policy IDs; lower scrutiny for freeform descriptions.
* **Acoustic & Semantic Confidence:** Detects when speech recognition alternatives (e.g., `event.results[i][j].transcript`) have multiple plausible interpretations.
* **Known Variant Catalog:** Recognizes common spelling splits:
  * *Sara* vs *Sarah*, *Jon* vs *John*, *Marc* vs *Mark*, *Bryan* vs *Brian*, *Shawn* vs *Sean*.
  * Street name suffixes and phonetically tricky names (*Coughlin*, *Worcester*, *Peachtree*).

### B. Natural, Low-Friction Confirmation Strategies
Instead of robotically asking the user to spell every single word (which destroys conversation flow):
1. **High Confidence:** Directly fills the value with zero interruption.
2. **Targeted Variant Check (Single & Multi-Word Names):** When a known variant is spotted—even inside a full legal name like *"Bryan Lopez"*—asks a rapid, natural question and preserves the rest of the name upon resolution:
   > *"Got it — is that Bryan with a Y or Brian with an I?"*  
   > *"Got it — is that Sarah with an H or Sara without an H?"*
3. **Phonetic Spelling Mode (including Accented Characters & NATO Phonetics):**
   > *"Could you spell that last name for me?"*  
   * The recognizer accepts single letters, accented characters (`J O S É`), spaced letters, or NATO/common phonetics (*"B as in Boy, R, Y, A, N"*), automatically assembling the normalized string without an extra LLM round-trip.
4. **Email Normalization:**
   * Automatically normalizes spoken emails (*"john dot doe at gmail dot com"*, *"maria arroba yahoo punto com"*) into `john.doe@gmail.com`.

## 4. Universal Form Engine: Web, PDF, and Telephony

Fluent's engine is decoupled from the DOM via the **`FormSession`** abstraction and **`Agent.fromSchema`**:

```javascript
class FormSession {
  // Scans input controls from active webpage
  static fromDOM(fields, metadata) { ... }
  
  // Extracts AcroForm fields & tooltips from PDF
  static fromPDF(fields, pdfMeta) { ... }
  
  // Ingests schema for headless / phone intake
  static fromSchema(intakeSchema) { ... }

  // Returns a headless page adapter so Agent runs without a browser DOM
  toPageAdapter() { ... }
}
```

### Telephony & Phone Intake Mode (`Agent.fromSchema`)
* When deployed as a phone agent (via WebSockets / SIP integration with providers like Twilio or LiveKit):
  * `Agent.fromSchema(schema, { llm, ui, userLang })` pairs the cognitive `Agent` directly with `session.toPageAdapter()`.
  * Uses the exact same cognitive milestone planner, 6th-grade explanations, spoken document location clues, and metacognitive spelling resolution.
  * When private fields (e.g., SSN, Member ID, USCIS A-Number, EIN) are reached, it enters `mode = 'type'` (which maps to **DTMF touch-tone keypad** on telephony or the masked private input box in the UI), ensuring strict PCI/HIPAA air-gap compliance.

## 5. User Experience & Conversational Flow

### A. Non-Intrusive Web Discovery & Non-Destructive Language Switching
* When visiting any webpage with forms or opening a PDF in Chrome:
  * Clicking the Fluent action opens the **Fluent Side Panel**.
  * Switching languages mid-session (`agent.setUserLanguage(newLang, newPhrases)`) dynamically re-translates the form and re-prompts the current question **without wiping already-completed fields**.

### B. Dynamic Milestones & Spoken + Visual Hint Cards
* The panel top bar displays: `Part 2 of 4: Contact Information · 3 left` alongside the language selector.
* If an obscure document field is reached (*Insurance Group Number*, *Member ID / Policy #*, *RxBIN*, *USCIS A-Number*, or *W-2 Box b EIN*):
  * Both in voice (`listen`) mode and private (`type`) mode, Fluent speaks a plain-language physical location clue (*"Look on your Green Card or Work Permit under 'USCIS#'..."*) and slides in an annotated visual hint card (`#doc-hint-card`) highlighting the exact zone and sample format (`A-098-765-432`).

### C. Fluid Jumps & Corrections
* Users can speak naturally at any point:
  * *"Wait, change my street address to 404 Elm Street"* $\rightarrow$ Updates field immediately, confirms verbally, and resumes where it left off.
  * *"Why do you need my income?"* $\rightarrow$ Explains in one sentence, then repeats the question.

### D. Bilingual Staff Verification Card
* At the end of the form, an interactive card (`#review-card`) displays:
  * All answers side-by-side in the user's native language and the form's official language (with sensitive fields masked as *"typed by you, kept private"*).
  * 1-click **Edit / Cambiar** buttons (`data-edit-field`) that jump `Agent` directly back to that field (`agent.editField(id)`).
  * Clear confirmation that the user maintains 100% control to review and submit the form.

## 6. Implementation Architecture & File Layout

* **`extension/lib/form-session.js`**: Unified abstraction over DOM, PDF, and headless schemas (`toPageAdapter()`), milestone tracker, document hint catalog, and bilingual review builder.
* **`extension/lib/metacognitive.js`**: Phonetic variant detection (`Bryan/Brian`, `Sarah/Sara`, `John/Jon`, `Marc/Mark`, `Steven/Stephen`, `Eric/Erik`, `Shawn/Sean`), multi-word name preservation, NATO/accented spelling normalization, and spoken email normalization.
* **`extension/lib/agent.js`**: Core conversation orchestrator with `Agent.fromSchema`, milestone tracking, spoken + visual document hints, metacognitive confirmation turns, non-destructive `setUserLanguage`, and `editField`.
* **`extension/lib/live.js` & `speech.js`**: Hesitant-speaker adaptive VAD (`detectHesitation`, `setAdaptivePause` 1800ms vs 500ms) and instant speech ducking (`duckSpeaking`).
* **`extension/panel/review-card.js`, `panel.js`, `panel.html`, `panel.css`**: Milestone progress bar, visual document hint cards, non-destructive language switching, and interactive bilingual review sheet.

## 7. Verification & Safety Guards

1. **Air-Gap Privacy Guard:** All private fields are masked, typed directly, and never sent to the LLM or telephone audio stream.
2. **Unit & Integration Test Suite:** Full test coverage across `tests/form-session.test.js`, `tests/metacognitive.test.js`, `tests/agent-milestones.test.js`, `tests/speech-vad.test.js`, and `tests/panel-ui.test.js`.
